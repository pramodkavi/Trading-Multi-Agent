# Slice 4 Step 4.5 — SPA Scaffold + S3/CloudFront Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The operator opens one HTTPS URL on phone or laptop, signs in through Cognito (password + TOTP), and sees an empty, responsive dashboard shell whose header proves the API path works end to end — served from a private S3 bucket behind CloudFront, which also forwards `/api/*` to the existing HTTP API so app and API share one origin.

**Architecture:** A Vite + React + TypeScript SPA in `dashboard-ui/` (Tailwind, react-router, TanStack Query, `react-oidc-context`/`oidc-client-ts`). At runtime it fetches `/config.json` (written by CDK from the stack's own Cognito/API values — no URLs baked into the bundle). `DashboardStack` gains a private S3 bucket (OAC), a CloudFront distribution with two behaviours (default → S3 via a viewer-request CloudFront Function that rewrites extension-less paths to `/index.html`; `/api/*` → the HTTP API with caching disabled and all viewer headers except Host), a security-headers policy, and a `BucketDeployment` that uploads `dashboard-ui/dist` + `config.json` and invalidates the cache. The Cognito app client gains the CloudFront callback/logout URLs (the localhost:8765 ones stay for the token helper). CI and the deploy workflows build the SPA before synth/deploy.

**Tech Stack:** Node 22 / npm 10; Vite 5, React 18, TypeScript 5 (strict), Tailwind CSS 3, react-router 6, @tanstack/react-query 5, react-oidc-context 3 + oidc-client-ts 3, Vitest + @testing-library/react + jsdom, ESLint 9 (flat config, typescript-eslint, react-hooks); AWS CDK (Python) `aws_s3`, `aws_cloudfront`, `aws_cloudfront_origins`, `aws_s3_deployment`; cdk-nag; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-18-serverless-dashboard-design.md` — §3.2 (React 18 + TS + Vite, Tailwind, react-router, TanStack Query polling; S3 private + OAC + CloudFront; CloudFront fronts `/api/*` for one origin; Cognito Hosted UI + code-with-PKCE via `react-oidc-context`; **access token in memory, refresh token in `localStorage`**), §3.5 (deploy workflow builds the SPA first; `BucketDeployment` with `Source.asset("dashboard-ui/dist")` + `Source.json_data("config.json", …)` built from the stack's own resources, `distribution=` invalidation; OIDC deploy role NOT extended; CI lints/type-checks the frontend), §4.2 (responsive — readable on a phone), §8 (S3 private; OAC; HTTPS only; HSTS; SPA fallback for 403/404 → `index.html`; Hosted UI callback restricted to the CloudFront domain), §9 (cost ≈ $0), §10 row **4.5** (checkpoint: login → empty shell renders at the CloudFront URL on phone and laptop), §12 (component library, icons, dark/light = follow system; Vitest + Testing Library).

- **Auth (design §3.2 + §8):** `react-oidc-context` `AuthProvider` with `authority = https://cognito-idp.<region>.amazonaws.com/<userPoolId>`, `client_id`, `redirect_uri`, `post_logout_redirect_uri`, `response_type = "code"` (PKCE is automatic), `scope = "openid email profile"`, `automaticSilentRenew = true`, `onSigninCallback` that strips `?code=&state=` from the URL. **Token storage split exactly as designed:** a custom `oidc-client-ts` `StateStore` (`SplitTokenStore`) keeps the full user (access + ID token) **in memory only** and persists **only** `{refresh_token, scope, profile.sub}` to `localStorage` under one key; on a fresh page load the stored stub is returned as an expired user so `oidc-client-ts` renews with the refresh token (no Hosted UI round-trip while the 30-day refresh token is valid). `signoutRedirect` uses Cognito's `/logout?client_id=…&logout_uri=…` (Cognito's end-session endpoint is not in its discovery doc — configure `metadataSeed.end_session_endpoint`). Signing out clears the store.
- **API calls:** one `apiFetch(path, init?)` helper: prefixes `config.apiBase`, adds `Authorization: Bearer <access_token>`; 401 → `signinSilent()` once then `signinRedirect()`; 503 with `{"reason":"db_resuming"}` → TanStack Query retry with backoff up to 60 s total (design §3.4) and a visible "waking the database…" state. Default query options: `refetchInterval: 60_000` while the tab is visible (`refetchIntervalInBackground: false`), `staleTime: 30_000`.
- **Shell:** responsive layout (mobile-first; nav collapses to a menu < 768 px); dark/light follows the OS (`prefers-color-scheme`) via Tailwind `dark:` + `darkMode: "media"`; routes `/` (Overview), `/signals`, `/funnel`, `/analytics`, `/markets`, `/health` — each an empty "Coming in Step 4.x" placeholder — plus `/callback` (OIDC) and a 404 page. Header shows: app name, signed-in email (from the ID token profile), **API status chip** = `GET /api/health` version (unauthenticated) + `GET /api/system/db` (authenticated) result (`ok` / `waking` / `error`), "updated N s ago", a refresh button, sign out. No charts, no data pages (Steps 4.6+).
- **CloudFront (design §8):** distribution `price_class=PRICE_CLASS_200` (includes India edge locations, which `PRICE_CLASS_100` lacks — the operator is in Sri Lanka; cost is pennies either way). HTTPS only (`viewer_protocol_policy=REDIRECT_TO_HTTPS`), default certificate (no custom domain), `http_version=HTTP2_AND_3`, `default_root_object="index.html"`.
  - **Default behaviour** → S3 via `S3BucketOrigin.with_origin_access_control(bucket)`; cache policy `CACHING_OPTIMIZED`; a **viewer-request CloudFront Function** (`cloudfront.Function`, JS 2.0 runtime) rewrites any URI with no file extension (no `.` in the last path segment) to `/index.html` — this is the SPA fallback. **Do NOT use distribution-level custom error responses** (they would also rewrite the API's real 403/404 into `index.html`). `index.html` and `config.json` are uploaded with `Cache-Control: no-cache`; hashed `assets/*` with `public, max-age=31536000, immutable` (two `BucketDeployment`s or `cache_control` per source set — implementer's call, documented).
  - **`/api/*` behaviour** → `HttpOrigin(<api-id>.execute-api.<region>.amazonaws.com)` (`Fn::Select`/`Fn::Split` of `http_api.api_endpoint`, HTTPS only), `allowed_methods=ALLOW_ALL`, `cache_policy=CACHING_DISABLED`, `origin_request_policy=ALL_VIEWER_EXCEPT_HOST_HEADER` (forwards `Authorization` and query strings; API Gateway needs its own Host). No CloudFront Function on this behaviour.
  - **Response headers policy** (both behaviours): HSTS `max-age=31536000; includeSubDomains`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, and a CSP on the default behaviour: `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self' https://cognito-idp.<region>.amazonaws.com https://<cognito-domain-host>; frame-ancestors 'none'; base-uri 'self'; form-action 'self' https://<cognito-domain-host>` (verify the built app has no inline script/style; Vite + Tailwind build do not emit any).
- **S3 bucket:** private, `block_public_access=BLOCK_ALL`, `enforce_ssl=True`, `encryption=S3_MANAGED`, `versioned=False`, `removal_policy=DESTROY` + `auto_delete_objects=True` (static build output; rebuilt on every deploy — my call; `auto_delete_objects` adds a small custom-resource Lambda).
- **Cognito client:** callback URLs `[TOKEN_HELPER_CALLBACK, "https://<distribution-domain>/callback"]`, logout `[TOKEN_HELPER_LOGOUT, "https://<distribution-domain>/"]` (distribution domain token; no dependency cycle: the distribution depends on the HttpApi, not on the authorizer/client).
