# Slice 4 Step 4.7 — Signal Journal (P3), Signal Detail (P2), Telegram Deep Links Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let the operator browse and filter every decision (`/signals`), open one decision's full agent chain (`/signals/:id`), and jump there from Telegram.

**Architecture:** Two independent deliverables, two PRs. **Part A** (frontend only; the 4.2/4.3 endpoints already exist and are live): pure logic modules (filter ↔ URL, CSV, timeline) under TDD, then the two pages, then links from the Overview. **Part B** (pipeline-side, own branch/PR, done after Part A is merged): `DashboardStack` publishes its CloudFront URL as a plain SSM String parameter; the scan Lambda reads it lazily and the Telegram formatters append a `…/signals/<id>` link; no link when the parameter is absent.

**Tech Stack:** Part A — React 19, TS 6 strict, Tailwind 3, TanStack Query 5 (`useInfiniteQuery`), react-router 7, Vitest + Testing Library. Part B — Python 3.11, boto3 SSM, AWS CDK (Python), pytest, mypy `--strict`, ruff.

**Spec:** `docs/superpowers/specs/2026-10-18-serverless-dashboard-design.md` §4.2 P2/P3, §7 (Telegram deep links), §10 row 4.7 (SPEC §4 Slice 4 row 4.7). Response shapes: `src/dashboard/api/schemas.py`, `src/persistence/models.py` (`StoredAgentRun`, `StoredSetupEvaluation`, `StoredReview`), `src/agents/critic/models.py` (`Resolution`), `src/agents/historian/models.py` (`HistoricalMatch`).

**Operator decisions (2026-10-25):** the candlestick chart on the detail page is **deferred to Step 4.9** (the same charting component serves P5); Telegram deep links ship in a **separate PR** after the pages.

## Global Constraints

- Read-only, signal-only: no write calls from the SPA; Part B only *reads* one SSM parameter. No new dashboard endpoints.
- SPA polling stays at the client default (60 s, no background polling). The detail page's raw agent output is fetched **only when its panel is expanded** (`GET /api/signals/{id}/runs/{run_id}`); the journal query key includes the filters so changing a filter resets the pages.
- Page size 50 (`limit=50`, server max 200); journal rows are trimmed server-side (no payload).
- All API text (reasoning, errors, tags, skip details, JSON) is rendered as React text — never HTML — long text wraps (`break-words`) and tables scroll inside an `overflow-x-auto` wrapper (no horizontal page scroll at phone width).
- Colour is never the only signal; reuse `Badge` / `Tone` and the palette from Steps 4.5–4.6. State (filters) lives in the URL query string so a view is linkable.
- Existing conventions: `*.test.ts(x)` beside the file, `stubApi`/`renderWithProviders`/`makeOverview` helpers in `dashboard-ui/src/test/`, `npm run lint` with `--max-warnings 0`.
- Part B: `mypy --strict`, `ruff check` + `ruff format --check` clean; **a missing, unreadable or malformed dashboard URL must never fail or delay a scan** (it only means "no link"); SSM parameter name is the static `/crypto-signals/dashboard-base-url`; no CloudFormation cross-stack reference in either direction (design §7, anti-goal §4.4); every Telegram message keeps the mandated "Signal only - manual execution required" footer; MarkdownV2 escaping rules in `formatter.py` apply to the link.

## Review Focus

**Part A**
1. Unknown or malformed signal id (`/signals/not-a-uuid`, valid-looking id that 404s) — expect a "Signal not found" state with a link back to the journal, never a crash.
2. CSV cells beginning with `=`, `+`, `-`, `@`, or containing quotes / commas / newlines / non-ASCII — expect spreadsheet-safe, correctly quoted output (no formula execution).
3. Rows with null fields (skips have no direction/entry; `outcome: null`; `realized_r: null`) — expect "—", never `null`/`NaN`/`undefined` text.
4. Detail timeline for incomplete chains (gate-rejected: no Historian/Skeptic/Judge steps; `NoMacroData` Skeptic sentinel; no setup; no Critic rows) — expect only the steps that exist, each labelled, nothing blank or crashing.
5. Filter edge cases — invalid/reversed dates, empty result set, changing a filter after "Load more", a `bad_cursor` 400 — expect an empty-state / inline error and pages reset on filter change.

**Part B**
1. The SSM parameter is absent, access-denied, empty or not an `https://` URL — expect no link and an unchanged message otherwise; the scan still completes.
2. A trailing slash on the stored URL — expect exactly one `/` before `signals/`.
3. MarkdownV2: the link text/URL contain reserved characters (`)`, `\`) — expect escaped per Telegram rules so the message still parses.
4. STILL_VALID Forecaster verdicts stay silent (no message, hence no link); AT_RISK / INVALIDATED / new signal / skip / judged-skip carry the link of *their own* signal id.
5. Cold start — the URL is read once per container, not once per message.
