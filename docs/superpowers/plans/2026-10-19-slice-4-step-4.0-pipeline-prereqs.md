# Slice 4 Step 4.0 — Pipeline Prerequisites Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the live pipeline record what the dashboard will need to show — the real scan session, per-agent LLM latency/tokens/cost, every Forecaster evaluation (including failures), a short Aurora-resume budget for request-scoped callers, and an account-level budget alarm — without building any dashboard code yet.

**Architecture:** Six small, independent changes to the existing scan Lambda code path and one CDK resource. Session derivation is a pure clock function consumed by `run_one_symbol`; LLM usage is carried from the Skeptic/Judge/Forecaster calls through LangGraph state into the existing `agent_runs` columns; Forecaster evaluations land in a new `setup_evaluations` table on both store backends; `DataApiSignalStore` gains a configurable resume-retry budget; `MonitoringStack` gains an AWS Budget routed to the existing alarm topic.

**Tech Stack:** Python 3.11, Pydantic v2, LangGraph, boto3 `rds-data` (Data API) + asyncpg (local), AWS CDK (Python) `aws_cdk.aws_budgets`, pytest (asyncio auto mode, `filterwarnings=error`).

**Spec:** `docs/superpowers/specs/2026-10-18-serverless-dashboard-design.md` — §5.2 (prerequisites), §5.2a, §3.4 (`resume_retries`), §9 (budget guardrail), §10 row **4.0**, §14 D1 (session fix).

## Global Constraints

- **Gate:** this plan starts on `main` **after** `feat/slice-2-step-2.14-critic-v0` has merged (design §14 D2). File line numbers below refer to that branch's versions. If the merge has not happened, stop and say so.
- Branch: `feat/slice-4-step-4.0-pipeline-prereqs` off `main`. One commit per task minimum.
- Universal checkpoints before the final commit (SPEC §5.1): `ruff check .`, `ruff format --check .`, `mypy --strict src/ scripts/`, `pytest` (all green, no new skips), pre-commit passes, no secrets in diff. Run with the project venv: `.\.venv\Scripts\python.exe -m <tool>`.
- `tests/` are not under mypy strict; `src/` and `scripts/` are.
- No new runtime dependency. (`aws_cdk.aws_budgets` ships inside the pinned `aws-cdk-lib==2.259.0`.)
- RDS Data API constraints apply to every new SQL statement: no array parameters; typeless NULLs need `::type` casts; timestamps go in as ISO strings via `_str_param` and come out through `_utc_iso(...)`.
- All DDL idempotent (`IF NOT EXISTS`). New tables are added with `CREATE TABLE IF NOT EXISTS`; the migration statement-count pin and `EXPECTED_TABLES` must be updated in the same commit as the DDL.
- **Live behaviour change (D1):** after this ships, any scan whose UTC clock falls in 21:00–00:00 or 00:00–08:00 records that session and rule 7 force-skips new proposals. The 22:03 daily-wrap scan therefore stops publishing new signals. Say this in the PR description and in `docs/PROJECT_STATE.md`.
- The schema reaches Aurora only via the operator's console invoke `{"mode":"migrate"}` after deploy (design §3.5). The plan's final checkpoint depends on that invoke.

## Review Focus

1. **08:00:00 UTC exactly** — a scan at the London open boundary must be `LONDON`, not `ASIAN` (half-open intervals, start inclusive). Pinned in Task 1 `test_session_for_boundaries`.
2. **Naive datetime into `session_for`** — must raise `ValueError`, never silently assume UTC. Pinned in Task 1 `test_session_for_rejects_naive`.
3. **Unknown model → `cost_usd=None`** — must persist as SQL NULL, not `0.0`, so the dashboard shows "unknown" rather than "free". Pinned in Task 2 `test_log_agent_persists_none_cost_as_null`.
4. **`record_setup_evaluation` itself failing** (DB down while recording an ERROR row) — must not abort the Forecaster loop or mask the original error. Pinned in Task 4 `test_error_row_write_failure_does_not_abort_run`.
5. **`resume_attempts=1`** — must raise on the first `DatabaseResumingException` with **no** sleep (an API-Gateway-bound caller cannot afford 5 s). Pinned in Task 5 `test_execute_single_attempt_raises_without_sleep`.
