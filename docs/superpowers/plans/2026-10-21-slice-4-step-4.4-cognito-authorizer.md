# Slice 4 Step 4.4 — Cognito User Pool + JWT Authorizer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the dashboard API's data routes reachable — and only for the operator: a Cognito user pool (one user, no self-signup), a public PKCE app client, an HTTP API JWT authorizer on `ANY /api/{proxy+}`, a Lambda-side defence that rejects any non-health request lacking authorizer claims, and a stdlib helper that fetches a token so the 4.4 checkpoint (no token → 401, valid token → 200) can be proven before the SPA exists.

**Architecture:** All new AWS resources live in `DashboardStack` (design §3.2 / §4.4: no cross-stack coupling). API Gateway validates the JWT before the Lambda runs (design §3.2 — no auth code in Python, unauthenticated calls cost nothing); FastAPI gets one small middleware as defence in depth (design §8). `GET /api/health` stays the only open route (more specific than the proxy). The helper (`scripts/dashboard_token.py`) runs authorization-code + PKCE against the Cognito Hosted UI with a one-shot `127.0.0.1:8765` listener.

**Tech Stack:** AWS CDK (Python) `aws_cognito`, `aws_apigatewayv2_authorizers.HttpUserPoolAuthorizer`, cdk-nag; FastAPI middleware; Python stdlib (`http.server`, `urllib`, `hashlib`, `secrets`, `webbrowser`) for the helper; pytest.

**Spec:** `docs/superpowers/specs/2026-10-18-serverless-dashboard-design.md` — §2 C1 (single user), §3.2 (JWT authorizer on every route except `/api/health`; Cognito Hosted UI + authorization-code-with-PKCE; advanced security off), §6.1 (OpenAPI behind the authorizer), §8 (no self-signup, strong password policy, optional TOTP MFA left to the operator, callbacks restricted, authorizer validates issuer/audience/expiry, Lambda additionally rejects requests without `requestContext.authorizer` claims), §9 (Cognito $0 at one user), §10 row **4.4** (checkpoint: token-less → 401; valid token → 200).

## Global Constraints

- Branch `feat/slice-4-step-4.4-cognito-authorizer` off `main` @ cea774b (4.2 + 4.3 merged, PR #15). One commit per task minimum. SPEC §5.1 checkpoints with the venv; pre-commit via `--from-ref main --to-ref HEAD`.
- **User pool** (`aws_cognito.UserPool`): `self_sign_up_enabled=False`; sign-in by **email** (case-insensitive); `feature_plan=FeaturePlan.LITE` (advanced security / threat protection off — paid tier); password policy min length **12**, require lowercase, uppercase, digits, symbols; temp password validity **3 days**; `mfa=Mfa.OPTIONAL`, `mfa_second_factor=MfaSecondFactor(otp=True, sms=False)` (no SMS cost); `account_recovery=AccountRecovery.EMAIL_ONLY`; `removal_policy=RemovalPolicy.RETAIN` (**operator decision 2026-10-21**: an accidental stack delete must not wipe the account; a recreated stack gets a new empty pool and the orphan costs nothing). Deletion protection on the CFN resource (`deletion_protection=True`) to match RETAIN.
- **Domain:** Cognito prefix domain `crypto-signals-dash-<account-id>` (`managed_login_version=ManagedLoginVersion.CLASSIC_HOSTED_UI`, works on the LITE plan).
- **App client** (`user_pool.add_client("DashboardSpaClient", ...)`): public (`generate_secret=False`); OAuth `authorization_code_grant=True` only (no implicit, no client-credentials); scopes `openid`, `email`, `profile`; callback `http://localhost:8765/callback`, logout `http://localhost:8765/` (Step 4.5 adds the CloudFront URLs); `auth_flows=AuthFlow(user_srp=True)` only (no `USER_PASSWORD_AUTH`, no custom); `prevent_user_existence_errors=True`; `enable_token_revocation=True`; access + ID token validity **1 h**, refresh **30 days**; `supported_identity_providers=[COGNITO]`.
- **Authorizer:** `HttpUserPoolAuthorizer("DashboardJwtAuthorizer", pool, user_pool_clients=[client])` (validates issuer + `aud`/`client_id` + expiry). Route `ANY /api/{proxy+}` → the existing Lambda integration with that authorizer. `GET /api/health` route unchanged and unauthenticated (more specific route wins). No CORS (same origin via CloudFront from 4.5).
- **Lambda-side defence (design §8):** an ASGI/FastAPI middleware: when the request runs under Lambda (`"aws.event" in request.scope`) and the path is not `/api/health`, require `event["requestContext"]["authorizer"]["jwt"]["claims"]` to be a non-empty mapping with a `sub`; otherwise respond **401** `{"reason": "unauthorized"}` without calling the route (no DB/AWS call). Outside Lambda (TestClient, local) it is a no-op — documented.
- **Throttle unchanged** (10 rps / burst 20). Access logs already JSON (authorizer rejections appear with `status` 401 and no `integrationLatency`).
- **cdk-nag:** `AwsSolutions-APIG4` must be satisfied on the proxy route by the authorizer (no suppression); `AwsSolutions-COG1` satisfied by the policy; `AwsSolutions-COG2` (MFA required) suppressed on the pool with reason "optional TOTP left to the single operator (design §8)"; `AwsSolutions-COG3` (advanced security) suppressed with reason "paid tier; single user (design §3.2 / §9)". Any other finding is fixed, not suppressed.
- **Outputs:** `DashboardUserPoolId`, `DashboardUserPoolClientId`, `DashboardCognitoDomain` (the Hosted UI base URL `https://<prefix>.auth.<region>.amazoncognito.com`), `DashboardJwtIssuer`.
- **Token helper (`scripts/dashboard_token.py`):** stdlib only (it ships in the Lambda code asset; must import nothing outside stdlib); CLI `python -m scripts.dashboard_token --domain <url> --client-id <id> [--port 8765] [--call <api-url>]`; PKCE **S256** verifier 64 chars from `secrets.token_urlsafe`; random `state` checked on return; one-shot HTTP server bound to **127.0.0.1** only, 120 s timeout; token exchange `POST {domain}/oauth2/token` (form-encoded `grant_type=authorization_code`, `client_id`, `code`, `redirect_uri`, `code_verifier`); prints the **access token** to stdout (nothing written to disk); `--call` performs `GET <api-url>` with `Authorization: Bearer <token>` and prints status + first 500 chars of the body. Errors exit non-zero with a one-line message, never a traceback with the token.
- No new runtime dependency; nothing in `src/` changes beyond the middleware; `/api/health` still DB/AWS/provider-free; read-only API.
- **Operator steps (docs, not code):** create the one user in the Cognito console (email as username, temporary password, "send an email invitation"), first login through the helper forces the password change; optional TOTP enrolment.
