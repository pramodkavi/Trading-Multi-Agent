# Slice 4 Step 4.3 — Funnel, Analytics, System Endpoints + Market Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the dashboard API's data surface — P4 decision funnel, P6 performance analytics (win rate, Skeptic value, equity curve, Critic reports/reviews), P7 system health (scans, agents + LLM cost, Forecaster sweeps, CloudWatch alarms + Lambda metrics, inferred config) and the market-data proxy (klines, signal chart, unrealised R) — plus the 4.2 placeholders it owed (alarm strip, unrealised R). Still FastAPI-only: nothing is routed through the HTTP API until Step 4.4.

**Architecture:** Same layering as 4.2. SQL lives in `queries.py`-style modules over `DashboardReader.read_rows`; bounded row sets are aggregated in **pure** Python modules (`funnel.py`, `analytics.py`, `system.py`) that reuse `classify`, `schedule.window_for` and the outcome rules, so every number is unit-testable without a DB. Market data goes through the existing `BinanceProvider` (`DataProvider` rule, design §3.2) built per request in `market.py`. CloudWatch reads go through a small `cloudwatch.py` (boto3 `cloudwatch`, same bounded `Config` as the Data API client, discovery **by name prefix**, design §7). The only infra change is three read-only CloudWatch actions on the dashboard role.

**Tech Stack:** Python 3.11, FastAPI + Mangum, Pydantic v2, boto3 `rds-data` + `cloudwatch`, ccxt via `BinanceProvider`, AWS CDK (Python) + cdk-nag, pytest.

**Spec:** `docs/superpowers/specs/2026-10-18-serverless-dashboard-design.md` — §3.2 (market data via `BinanceProvider`), §4.2 P4 / P6 / P7 (and P1's alarm badges + unrealised R), §5.2a (outcome ground truth + Skeptic-value definition), §6.1 endpoint table, §7 (discover alarms/function by name prefix, no cross-stack refs), §8 (role: `cloudwatch:DescribeAlarms`/`ListMetrics`/`GetMetricData`, no SSM, no `lambda:*`; config panel **inferred** and labelled so), §10 row **4.3** (checkpoint: same test pattern; `EXPLAIN` on the funnel query < 500 ms at 10 k signals, NFR-4.3).

- Branch `feat/slice-4-step-4.3-analytics-system-endpoints`, **stacked on** `feat/slice-4-step-4.2-read-only-queries` @ f813a63 (4.2 is not merged yet; merge 4.2 first, then this PR rebases cleanly onto main). One commit per task minimum.

- Read-only; no schema change; no new dependency; nothing routed through the HTTP API; `/api/health` stays DB-free and AWS-free; every SQL value bound by name (design §8).
- Data API 1 MB cap: every query returns **minimal columns** (no `payload::text`, no `output::text` beyond named `->>` extracts); every period parameter is **capped** (funnel/analytics ≤ 365 days; default 30 for funnel, 90 for analytics) — a larger range → 422.
- **Outcome rule (design §5.2a, verbatim):** use `decision_resolutions` when a row exists for the signal, else `signals.outcome`; every analytics response carries `source_counts: {"replayed": n, "forecaster": m}`. Decisive = WIN/LOSS; `win_rate = wins / (wins + losses)`, `null` when 0 decisive. Equity R = `realized_r` when replayed, else WIN → `+risk_reward_ratio`, LOSS → `-1`, BREAKEVEN/INVALIDATED/EXPIRED → `0`; unresolved decisions are omitted. Vetoed / gate-rejected **counterfactuals only from `decision_resolutions`**.
- **Skeptic value (design §5.2a, verbatim):** an objection counts when `recommends_against` is true **or** `severity == "HIGH"`; Judge ruling SKIP → `respected`, PUBLISH_WITH_CAVEAT → `overruled_with_caveat`, PUBLISH → `overruled`; three buckets; NoMacroData runs (`"provider" in output`) excluded and counted as `no_macro_data_excluded`.
- **Market data:** `BinanceProvider` built **per request** and closed in `finally` (aiohttp sessions are loop-bound; Mangum keeps one loop per container — per-request is the simple safe choice). Symbols restricted to `DashboardSettings.scan_symbols` (else 400 `{"reason":"unknown_symbol"}`). Any `ProviderError` → **502** `{"reason":"market_unavailable"}` (registered handler; message logged, not echoed). Klines `limit` 1..500, default 200; timeframe ∈ `Timeframe`.
- **Unrealised R** on setup cards (overview + `/api/setups/open`) is **best-effort**: one latest-price fetch per distinct OPEN-setup symbol, concurrent, overall budget **5 s** (`asyncio.wait_for`); on timeout/ProviderError the field stays `null` and `unrealised_r_note = "price unavailable"`; otherwise note `null`. Formula: LONG `(price - entry) / (entry - stop)`, SHORT `(entry - price) / (stop - entry)`, rounded to 2 dp. Never fails the route.
- **CloudWatch:** client built lazily per container with `Config(connect_timeout=3, read_timeout=10, retries={"max_attempts": 1})`; calls run via `asyncio.to_thread`. Alarms = `DescribeAlarms(AlarmNamePrefix="CryptoSignals-Monitoring-")`; scan function discovered via `ListMetrics(Namespace="AWS/Lambda", MetricName="Invocations")` dimension `FunctionName` starting `CryptoSignals-Compute-ScanLambda`. Any `ClientError`/`BotoCoreError` on these → the **section** is `null` with `note="cloudwatch unavailable"`, HTTP 200 (a CloudWatch hiccup must not take the page down).
- **IAM (design §8):** add `cloudwatch:DescribeAlarms` on `arn:aws:cloudwatch:<region>:<account>:alarm:CryptoSignals-Monitoring-*`, and `cloudwatch:ListMetrics` + `cloudwatch:GetMetricData` on `*` (these two have no resource-level permissions — justify the `AwsSolutions-IAM5` suppression in code). Still no `ssm:`, `s3:`, `lambda:`.
- **Config panel is inferred** (design §8): watchlist = union of `scan_runs.symbols` in the last 7 days; model = latest `agent_runs.token_usage->>'model'`; macro providers configured = any of the last 10 skeptic outputs lacks `provider` (i.e. a real objection); Langfuse configured = `DashboardSettings.langfuse_base_url is not None` (the dashboard's own setting, labelled as such); schedule from `src.common.schedule.SCAN_WINDOWS`. Every value carries `"inferred": true` except the schedule.
- NFR-4.3 checkpoint ruling: the funnel/analytics SQL is a single indexed range scan on `signals.created_at` + PK/LATERAL lookups; we cannot seed 10 k rows (no writes, no local Postgres). Task 5 runs `EXPLAIN (ANALYZE, BUFFERS)` against the **live** DB through the aws-mcp read path if the token is valid, else documents the query plan as a 🟡 verify-after-deploy item. (My call.)
- Deferred, stated so nobody looks for it: `/api/markets` (P5 tiles) → Step 4.9 with its page; asyncpg twins; per-sweep Forecaster history beyond 7 days.
