# Slice 4 Step 4.2 — Read-Only Queries + Overview / Setups / Signals Endpoints Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the dashboard API its data layer and the P1–P3 endpoints — overview, open setups, the paged signals journal and the per-signal lifecycle — reading Aurora through the RDS Data API with a 1-attempt resume budget that surfaces as HTTP 503 `db_resuming`, all unit-tested on SQL shape and parsing, **without exposing any of it through the HTTP API until Step 4.4 adds the JWT authorizer**.

**Architecture:** `DataApiSignalStore` gains one public read seam (`read_rows`) so dashboard SQL lives in `src/dashboard/api/queries.py` and never touches a private method. `DashboardSettings` + `deps.py` build one store per Lambda container with `resume_attempts=1`; app-level exception handlers map Aurora's resume error to 503 and other Data API errors to 502. `classify.py` re-exports the Critic's `DecisionKind` / `classify` and adds a column-level variant whose SQL `CASE` twin filters the journal server-side (parity-tested). Two pipeline-side pure helpers are widened/added: `gather_risk_context(snapshot=None)` and `src/common/schedule.py` (scan windows → "next scan" and "which window did this run belong to"). The FastAPI app gets four routers; the HTTP API keeps its single `/api/health` route. The stage's access-log format becomes HTTP-API JSON (4.1 follow-up).

**Tech Stack:** Python 3.11, FastAPI 0.150 + Mangum 0.22 (already in the `dashboard` extra), Pydantic v2, boto3 `rds-data` via `DataApiSignalStore`, AWS CDK (Python) `aws_apigatewayv2` + `aws_apigateway.AccessLogFormat`, pytest (`asyncio_mode=auto`, `filterwarnings=error`).

**Spec:** `docs/superpowers/specs/2026-10-18-serverless-dashboard-design.md` — §3.3 (DashboardSettings), §3.4 (resume budget → 503 `{"reason":"db_resuming"}`; paging default 50 / max 200; trimmed lifecycle payload with full JSON per step on expand), §4.2 P1–P3, §5.1 (decision classification derived, not stored; a "scan" is an invocation bucketed by window), §5.3 (reuse `gather_risk_context`; split a store-only helper if it needs a snapshot), §6.1 endpoints `/api/system/db`, `/api/overview`, `/api/setups/open`, `/api/signals`, `/api/signals/{id}`, §6.2 layout, §8 (defence: reject requests without authorizer claims — **Step 4.4**), §10 row **4.2**, §14 D2 (`classify.py` is a thin re-export of `critic.inventory`).

## Global Constraints

- Branch: `feat/slice-4-step-4.2-read-only-queries` off `main` at `c3ecb80` (Step 4.1 merged, PR #14). One commit per task minimum.
- Universal checkpoints (SPEC §5.1) with the venv: `ruff check .`, `ruff format --check .`, `mypy --strict src/ scripts/`, `pytest` (all green, no new skips), pre-commit via `pre_commit run --from-ref main --to-ref HEAD` (local git 2.20.1 cannot run `--all-files`), no secrets in the diff.
- **No new runtime dependency.** No new tables, no schema change, no writes anywhere (design D3 / FR-7.4). Every statement is parameterised through `DataApiSignalStore` helpers; no string formatting of user input into SQL (design §8). Filter values go in as named params; only whitelisted column/direction tokens may be interpolated.
- RDS Data API rules: no array parameters; typeless NULLs need `::type` casts; timestamps in as ISO strings (`_str_param`), out via `_utc_iso(...)`; JSONB out as `::text` and parsed with `_parse_jsonb_field`; `cost_usd` out as `::double precision`.
- **Store resume budget for the dashboard: `resume_attempts=1`** (design §3.4) — the first `DatabaseResumingException` propagates with **no sleep** and becomes **HTTP 503** `{"reason":"db_resuming"}` with header `Retry-After: 10`. Any other `botocore.exceptions.ClientError` → **HTTP 502** `{"reason":"db_error"}` (message logged, not echoed). `/api/health` stays DB-free (Step 4.1 tests remain green).
- **Paging** (design §3.4): `limit` default **50**, max **200** (`limit` outside 1..200 → **422** from `Query(ge=1, le=200)`; the design's "max 200" is enforced by rejection, not clamping — simpler and honest); keyset cursor on `(created_at DESC, id DESC)`; `cursor` is opaque: `base64url(json.dumps([created_at_iso, str(id)]))`; an undecodable cursor → **400** `{"reason":"bad_cursor"}`. Responses carry `next_cursor: str | null`.
- **Decision kind** (design §5.1): `PUBLISHED` (proposal, Judge ruling ≠ SKIP or no Judge run), `VETOED` (proposal, Judge `ruling == "SKIP"`), `GATE_REJECTED` (skip with non-empty `payload->>'violated_rule'`), `NO_SETUP` (other skips). "Actually published" additionally means an `active_setups` row exists — the journal row carries `has_setup: bool` so the UI can show it; the kind itself follows the Critic's definition unchanged.
- **Scan windows** (SPEC §5 / `SchedulingStack`): scans fire at **08:03, 13:03, 15:03, 22:03 UTC**; labels `LONDON`, `NY`, `OVERLAP`, `DAILY_WRAP`. A `scan_runs` row belongs to the window whose fire time is the latest one ≤ `started_at` within 30 minutes; otherwise it is `AD_HOC`.
- **Risk budget numbers must match the gate** (design §4.2 P1 / §5.3): open setups vs cap **3**, published in the last **24 h** vs cap **5**, loss streak vs **3** and whether the **24 h** pause is active — computed through `risk_gates.gather_risk_context` and `check_*` functions, never re-implemented.
- **Nothing in this step is routed through the HTTP API.** The HTTP API keeps exactly one route (`GET /api/health`); the new endpoints exist in the FastAPI app and are exercised by `TestClient` and direct Mangum invocation. Step 4.4 adds `ANY /api/{proxy+}` behind the Cognito JWT authorizer. (My call: routing journal data without auth would expose it and let any scanner wake Aurora.)
- `DashboardSettings` never loads the agent `Settings` (design §3.3). Fields: `db_cluster_arn: str`, `db_secret_arn: str`, `db_name: str = "signals"`, `aws_region: str | None = None`, `scan_symbols: list[str]` (CSV env `SCAN_SYMBOLS`, same parsing as `Settings`, default watchlist), `log_level: str = "INFO"`, `langfuse_base_url: str | None = None`. `env_file=".env"`, `extra="ignore"`, `case_sensitive=False`. Missing ARNs raise at first use, not at import.
- Deferred, stated so nobody looks for it: asyncpg twin of the dashboard queries (the dashboard Lambda only ever uses the Data API; the integration test cannot run on this machine); `unrealised_r` on setup cards and the health strip's CloudWatch alarm states (both need providers/IAM that Step 4.3 adds — the response fields exist and are `null` with a `"pending"` note); `/api/signals/{id}/chart` (4.3, needs klines).
