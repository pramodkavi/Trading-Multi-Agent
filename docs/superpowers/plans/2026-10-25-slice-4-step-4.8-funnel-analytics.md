> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Funnel and Analytics placeholders with the real P4 and P6 pages, so the operator can see where proposals die on the way to publication and whether published signals (and the Skeptic) are earning their keep.

**Architecture:** Frontend only — the 4.3 endpoints (`/api/funnel`, `/api/analytics/*`, `/api/critic/*`) are live. Pure view-model logic (stage math, rejection series, win-rate labelling, equity series) under TDD, then small presentational components, then the two pages. Every chart ships with a data table fallback (accessibility + testability in jsdom); tests assert on the table/text, not on SVG geometry.

**Tech Stack:** React 19, TS 6 strict, Tailwind 3, TanStack Query 5, react-router 7, Recharts (exact-pinned, per design §4.2 P6), Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-10-18-serverless-dashboard-design.md` §4.2 P4 / P6, §5.2a, §10 row 4.8 (SPEC §4 Slice 4 row 4.8). Response shapes: `src/dashboard/api/schemas.py` (`FunnelResponse`, `WinRateResponse`, `SkepticValueResponse`, `EquityCurveResponse`, `CriticReportsPage`, `CriticReportOut`, `ReviewsPage`), `src/dashboard/api/funnel.py` (`FunnelGroup`), `src/dashboard/api/analytics.py` (`WinRateBucket`, `SkepticBucket`, `EquityPoint`), `src/dashboard/api/queries.py` (`CriticReportSummary`, `ReviewSummary`), `src/dashboard/api/period.py` (422 when since ≥ until or range > 365 d).

**Operator decisions (2026-10-25):** Recharts for the charts, with the `dataviz` skill's palette/accessibility rules (load that skill before writing chart code); the Critic report's markdown is shown as **plain preformatted text** (no markdown renderer — avoids a dependency and an XSS surface); frontend only.

## Global Constraints

- Read-only, signal-only: no write calls, no backend change, no new endpoints.
- Polling stays at the client default (60 s, visible tab only). Period queries send only a **UTC-midnight `since`** (e.g. `2026-10-18T00:00:00Z`) and omit `until` (the API defaults it to now): the query key is then stable for a whole day instead of changing every minute.
- Periods offered: last **7 / 30 / 90 days** (funnel default 30, analytics default 90 — the API defaults); every request stays under the API's 365-day cap.
- A win rate is **never shown without its sample size**; `win_rate: null` renders `—` (not 0%); a bucket with fewer than **5 decisive** outcomes carries a "low sample" tag.
- Counterfactual curves (vetoed / gate-rejected) are labelled as such and never summed into the published curve.
- All API text (rule names, tags, summaries, report markdown) is rendered as React text, wrapped (`break-words`); tables scroll inside `overflow-x-auto` (no horizontal page scroll at phone width); report markdown goes in a `<pre>` (plain text).
- Colour is never the only signal (labels, patterns/dash styles for lines, a data table for each chart); contrast per the existing palette; follow the `dataviz` skill (categorical series limited, no rainbow, validated palette, tooltips optional but never the only way to read a value).
- Dependency: add `recharts` pinned to an exact version at least 14 days old (`npm view recharts time` to choose; confirm its peer range accepts React 19); no other new dependency. The build must stay under the CSP `script-src 'self'; style-src 'self'` (Recharts sets styles through React props/CSSOM, not inline `<style>` blocks — verify on the deployed page).
- Existing conventions: tests beside the file, `stubApi`/`renderWithProviders`/`jsonResponse` helpers and fixtures in `dashboard-ui/src/test/`, `npm run lint` with `--max-warnings 0`; files end with a newline (CI pre-commit `end-of-file-fixer`).

## Review Focus

1. Sparse / empty data (no scans in range, no published signals, no outcomes yet, Critic tables empty) — expect an explicit empty state per section, never a blank chart, `NaN`, `Infinity` or a division by zero.
2. Percentages with a zero denominator (stage with 0 in the previous stage; `decisive: 0`) — expect `—`.
3. A period change while data is loading, and a 422 (`since must be before until`) — expect the previous data kept / an inline error, never a crash.
4. Many distinct rejection rules (more than the palette allows) — expect the top few plus an "Other" bucket, with the full list in the table.
5. Hostile / long strings (a rule name, tag or Critic summary with HTML or 500 chars) — expect plain wrapped text.

### Task 2: Pure view-model logic

**Files:** Create `lib/funnel.ts`, `lib/analytics.ts`; Test `lib/funnel.test.ts`, `lib/analytics.test.ts`.

**Interfaces:**
- Consumes: `FunnelGroup`, `RejectionCount`, `WinRateBucket`, `SkepticBucket`, `EquityCurveResponse`, `EquityPoint` (Task 1); `Tone`.
- Produces (`lib/funnel.ts`):
  - `interface Stage { id: "scans" | "symbols" | "proposals" | "gate_passed" | "published"; label: string; count: number; ofPrevious: number | null; ofScanned: number | null }` and `funnelStages(totals: FunnelGroup): Stage[]` — five stages in that order (`scans`, `symbols_scanned`, `proposals`, `gate_passed`, `published`); `ofPrevious` = count / previous count (`null` for the first stage or when the previous count is 0); `ofScanned` = count / `symbols_scanned` (the per-symbol scan count; `null` when that is 0).
  - `judgeBreakdown(totals): { publish: number; caveat: number; skip: number; none: number }`.
  - `interface RejectionSeries { rules: string[]; rows: Record<string, string | number>[] }` and `rejectionSeries(groups: FunnelGroup[], topN = 5): RejectionSeries` — `rules` = the `topN` rules by total count across groups, descending, plus `"Other"` when more exist (summing the rest); each row is `{ key: group.key, <rule>: count… }` with 0 for missing; empty input → `{ rules: [], rows: [] }`.
  - `groupLabel(key: string, groupBy: "day" | "window" | "symbol"): string` — day keys `YYYY-MM-DD` → `MM-DD`; others unchanged.
- Produces (`lib/analytics.ts`):
  - `formatWinRate(rate: number | null): string` → `"62.5%"` / `"—"`; `isLowSample(decisive: number): boolean` (`decisive < 5`).
  - `winRateRows(buckets: WinRateBucket[]): { key: string; label: string; pct: number | null; n: number; decisive: number; wins: number; losses: number; lowSample: boolean }[]` — sorted by `n` descending then `key`; for `by === "time"` callers sort by key ascending (provide `sortByKey`).
  - `skepticRows(v: SkepticValueResponse): { id: "respected" | "overruled_with_caveat" | "overruled"; label: string; n: number; wins: number; losses: number; pct: number | null; note: string }[]` — labels "Judge respected the objection (veto)", "Overruled with a caveat", "Overruled"; `note` for `respected` says outcomes are counterfactual replays.
  - `equityLines(c: EquityCurveResponse): { id: "published" | "vetoed" | "gate_rejected"; label: string; counterfactual: boolean; points: { t: number; cumulativeR: number }[]; finalR: number | null }[]` — `t` = epoch ms of `at`; `finalR` = last `cumulative_r` or `null` for an empty curve; vetoed / gate_rejected have `counterfactual: true`.
  - `hasAnyPoints(c): boolean`.
